# 状态管理与数据流深度解析

SlideGrid Studio 的状态管理不仅负责数据存储，还集成了历史追踪、跨页面同步和复杂的数据迁移逻辑。

## 1. 响应式原子：Zustand Store (`useStore.ts`)

应用的状态被建模为一个单向数据流的 Store。

### 1.1 核心状态树 (`ProjectState`)
- **`pages`**: 核心页面数组，包含所有的排版与内容数据。
- **`theme` / `designSystem`**: 全局视觉规范。
- **`isLoaded`**: 异步加载状态标志。
- **`hasUnsavedChanges`**: 脏检查标志，用于驱动自动保存。

---

## 2. 撤销/重做：深度快照机制

我们没有使用传统的命令模式 (Command Pattern)，而是使用了更简单的 **快照模式**。

### 2.1 历史栈管理
- **触发时机**: 只有在真正的用户交互（如 `onBlur` 或按钮点击）时才会调用 `pushHistory()`，而非键盘输入的每一个字符，以防止历史记录被微小输入填满。
- **深度限制**: 默认保留最近 50 步操作。
- **不可变性**: 利用深拷贝（针对 Pages 和 Theme）确保 Undo 后的状态不会被后续操作干扰。

---

## 3. 跨页面全局同步算法

幻灯片应用的一个常见痛点是修改一处样式（如页码样式）需要手动同步到所有页面。

### 3.1 同步逻辑 (`updatePage`)
当某个页面更新时，Store 会执行以下检查：
1. **全局字段识别**: 识别修改的字段是否属于 `GLOBAL_FIELDS`（如 `counterStyle`, `footer`, `titleFont`）。
2. **全量广播**: 如果检测到全局字段变更，循环遍历 `pages` 数组，将该变更应用到所有页面引用上。
3. **静默更新**: 该同步过程不应再次触发 `pushHistory()`，以保持撤销栈的整洁。

---

## 4. 持久化循环：从内存到 IndexedDB

应用采用了 **Hybrid Auto-save** 策略：

### 4.1 自动保存触发器
- **定时驱动**: 每隔 3000ms，系统会静默检查 `hasUnsavedChanges` 标志。
- **原子保存**: 使用 `utils/db.ts` 将完整的 `ProjectData` 序列化并存入 IndexedDB。
- **崩溃恢复**: 重启时，应用会优先检查 IndexedDB 中的 `latest_snapshot`，确保用户不会丢失未手动保存的内容。

---

## 5. 数据版本演进 (Migrations)

随着 Zine Mode 的引入，数据结构发生了巨大变化。

### 5.1 迁移流水线 (`v2-to-v3.ts`)
当数据从磁盘或 IndexedDB 加载时，它会流经一系列迁移函数：
1. **资产解耦**: 将 Base64 抽离为文件引用。
2. **令牌注入**: 将默认的 `DesignSystem` 注入旧项目。
3. **架构重组**: 将旧的 `titleFont` 配置映射到新的主题系统中。
4. **Zod 校验**: 最终确保输出数据符合最新的 `ProjectData` 接口规范。
